# 代码库诊断与重构建议 · 2026-11-01

对象：`Anton Repponen风格化工具/index.html`（合集 `TheLiangSui风格化工具` 内置的同一份）
做法：量化体检 + 问题定位 + 阶段化重构路线。**不建议推倒重写**，理由见第 5 节。

---

## 1. 结论摘要

这不是"写得乱"的问题，是**结构性问题**：一个 4216 行的单文件里，UI、状态、渲染、撤销、
工程读写、文件 IO 全部共享同一个作用域和同一个可变全局对象 `S`。任何一处结构改动都会
牵动三四个地方，而且**失败是静默的**（测试会少跑一段而不报 FAIL）。

今天 5 项需求里 4 项卡住的直接原因就是这个结构，不是能力问题。

## 3. 主要问题清单

### P0 · 直接造成"改不动"

**P0-1 全局可变状态没有收口（397 处 `S.` 写入）**
`S` 是一个裸对象，任何函数都能就地改它。改了要不要重渲染、重渲染哪几块，全靠调用方记得。
于是产生 `renderAll()` 这种"全家桶重绘"，又衍生出"重绘会重建 DOM → 输入框失焦 / 拖拽中断"
的一连串补丁（历史上真的踩过：`bindNum` 的 `change` 里重建面板导致失焦）。

**P0-2 UI 是字符串拼出来的，再用 id 去找回来**
`renderProps()` 用 184 行字符串拼出面板，然后 `getElementById` 逐个绑定。结构一动，
绑定和测试同时断；而断掉的方式是**抛异常**，被测试框架吞掉，表现为"总数少了一半却零 FAIL"。
今天实测：331 → 175，一条 FAIL 都没有。

**P0-3 测试和实现耦合在同一个页面**
自测靠 `window.__tool` 导出 28 个内部函数来驱动。测试成了第二个"调用方"，
任何内部改名或结构变化都要同步改测试，重构成本翻倍。

### P1 · 拖慢每一次迭代

**P1-1 派生状态靠手写同步**：图层面板、属性面板、状态栏、按钮可用性，各自有各自的
`render*`，谁先谁后、谁该调谁，没有唯一入口。

**P1-2 无类型、无构建、无 lint**：拼错变量名只能运行时炸；`S.layers` 里混着 `kind`、
`img`、`parts`、`_col` 各种可选字段，没有一处声明能说明"一个图层到底有什么"。

**P1-3 死代码与兼容层堆积**：`makeGrid`、`doRandomBox`、`boxSizeRange` 已被新方案取代，
但仍留在文件里（因为测试还在用），两套并存的代码互相干扰——今天替换面板就是这么炸的。

### P2 · 长期隐患

- 65 处事件监听无统一生命周期，面板重建即泄一次（靠元素被 GC 兜着）。
- 历史栈用整份 `JSON.stringify(layers)` 快照，图层多了以后内存和耗时都会上去。
- 图片层位图走"不可枚举属性 + id 注册表"绕开序列化，这是个补丁，不是设计。

## 4. 成因分析

1. **起点合理，但没有"该拆了"的分界线。** 单文件最初是正确的（便于分发、便于 iframe 内嵌），
   问题是图表层的复杂度增长后没有换挡。
2. **AI 写代码的默认倾向是"加在当前文件里"。** 每次需求都在同一个作用域里追加函数，
   没有新建模块的动作，因为单文件项目里"新建模块"成本很高（要自己维护加载顺序）。
3. **缺少护栏，失败静默。** 没有类型检查、没有 lint、测试异常被吞 —— 三个"静默"叠加，
   错误只能在用户面前暴露。
4. **重构没有发生过，只有局部补丁。** 于是补丁之间互相耦合，形成事实上的"屎山"。
5. **验证手段单一。** 只有"331 项自测全绿"这一个信号，而它恰好会静默跳过一段。

---

## 5. 为什么不建议推倒重写

- 331 项自测是**资产**：它们记录了两年踩出来的行为细节（dpr 坐标不变量、锁定层穿透、
  合并形状的像素级裁剪、撤销里位图回挂）。重写等于把这些全部作废。
- 真正值钱的是算法与行为契约，不是那 3137 行组织方式。
- 正确做法是**绞杀式重构**：外层换架构，内层逻辑一块一块搬，每一步都能跑回 331 项。

## 6. GitHub 上的成熟方案（已核实）

| 方案 | 作用 | 许可 |
|---|---|---|
| **vite + vite-plugin-singlefile**（richardtallent） | 模块化开发，构建时把 JS/CSS 全部内联成**一个 HTML**。产物形态完全不变，合集 iframe、单文件分发、双击打开都不受影响 | MIT |
| **@preact/signals-core** / **nanostores** | 1–2KB 的细粒度状态，替代手写 `renderAll` 全家桶 | MIT |
| **lit**（~6KB）或原生 Web Components | 组件化 UI，替代字符串拼 HTML + id 查找 | BSD-3 |
| **vitest + playwright** | 把测试从页面里搬出来，纯逻辑与交互分开跑 | MIT |
| **eslint + typescript（checkJs）** | 拼写/类型错误在编辑期暴露，不再靠运行时 | MIT |

**核心一条**：`vite-plugin-singlefile` 让"模块化"和"单文件分发"不再是二选一。
这是这个项目重构的关键前提——没有它，拆文件就等于放弃现在的分发方式。

## 阶段 2 已完成（2026-11-01 22:40）—— 面板改为构造节点

### 做了什么

新增 `src/js/00b-DOM构造.js`：`h(tag, props, ...kids)` / `hs()`（SVG 命名空间）/ `icon()` / `cells()` / `info()` / `stack()`。

属性面板与图层列表从「拼字符串 → innerHTML → getElementById 找回」改成「先建控件、拿到变量、拼装、就地绑定」。

```
改前：'<input type="text" id="pName" value="'+escapeHtml(L.name)+'">' … 190 行字符串
      → 再 bind('pName', ...) 用 id 找回来（id 拼错 = null，静默失效）

改后：const pName = h('input', { type:'text', value: L.name });
      … pName.addEventListener('change', ...)   // 变量就在手边
```

`cellNum()` / `ctlNum()` 现在返回**节点**而不是字符串，且把数字框挂在 `cell._inp` 上，
调用方拿到单元就能直接 `bindNum(cell._inp, ...)`，不再按 id 查。

### 怎么证明没改坏

写了 `dev/dom-snapshot.js`：把 `#props` / `#layerlist` 序列化成**规范化签名**
（标签、属性、输入框的 value 属性、option 选中值、样式串排序），覆盖 9 种状态
（无选中 / 普通层 / 乱序 / 间序 / 锁定 / 合并形状 / 图片层 / 组展开 / 组折叠）。

改前抓一份，改后抓一份，逐节点 diff：

```
改前 vs 改后：唯一差异是 pSeed（随机种子），
              同一份构建连跑两次也会出现同样 7 条差异 → 与改写无关
```

### 阶段 3 已完成（同日）—— 渲染调度

`renderAll()` 不再「一律全套重建」，改为先算签名：

| 签名 | 内容 |
|---|---|
| `layerListSig()` | 每个层的 `oid(对象)` + 显示相关字段 + 源图版本 + 合集状态；**不含选中态** |
| `propsSig(L)`  | `oid(L)` 或 `'none'` + 面板上出现的每个字段 |

- 图层列表签名没变 → 只 `syncLayerSel()` 切 class，**不重画任何缩略图**
- 属性面板签名没变 → 不重建，**展开中的下拉不会被无关刷新掐掉**
- `oid()` 是 WeakMap 发的唯一序号：撤销 / 读盘后图层是新对象，即使字段全等也会重建，
  否则行里的监听还挂在旧对象上（这类 bug 最难查）

### 顺带清理

- `document.getElementById()` 135 处 → `$()`：带 `isConnected` 失效检测的查询缓存
- `innerHTML =` 15 处 → 2 处（只剩项目库卡片与 `h()` 里的 `html:` 逃生口）
- 文件名去掉拆分脚本留下的碎片：`13-随机function.js` → `13-随机.js` 等 22 个
  （改名后重新构建，`cmp` 与原产物**逐字节一致**，证明纯改名零影响）

### 动机

阶段 2/3 引入了两个**手写字段清单**：`propsSig` / `layerListSig` 自己列字段，
`stripeFor` 的缓存键也自己列。这三处是新的地雷 —— 加一个参数忘了登记，
表现就是「改了值但画面/面板不动」，正是这两年反复踩的那种 bug。

现在全部改成**自动收录**：

```js
function stableStr(o){            // 以 _ 开头的键（_col 等缓存）自动排除
  return JSON.stringify(o, function(k, v){
    if (k && k.charAt(0) === '_') return undefined;
    return v;
  });
}
```

- `propsSig(L)` = `oid(L) + 源图尺寸 + stableStr(L)`
- `layerListSig()` = 每层 `oid(L) + stableStr(L)` + 合集 + 源图版本
- `stripeFor` 的缓存键 = 源图版本 + 取样位置 + `stableStr(L)`

顺带删掉了属性面板里 11 处手工 `dirty()`（原本用来作废像素缓存）。
删完「改 block 后缓存正确失效」这条老测试仍然通过 —— 证明自动键确实够用。

新增两条守卫：

```
PASS 新字段自动纳入签名（无需登记）
PASS 新像素参数自动进缓存键（不用手写清单）
PASS 下划线字段不进签名
```

### 一个设计取舍

**框选只能从列表空白处起手**，行上拖动保留为排序。理由：同一块区域不能既排序又框选，
而 HTML5 原生拖拽无法可靠地与自绘手势共存。为了这一条，列表底部固定留了 44px 空白，
层数满了也能从这里起手。同时补了「Shift + 点击 = 范围选择」——批量选层最常用的其实是这个。
