## 0. 怎么用

**桌面版（推荐）**：双击 `时间拉伸.exe`
**网页版**：双击 `index.html`，或把图片直接拖进浏览器窗口

两者功能完全一致，共用同一份 `index.html`。图片全程不离开本机。

基本流程：

1. 导入图片（拖进来 / 点「导入图片」/ `Ctrl+V` 粘贴）
2. 在画面上拖拽框选矩形 —— 松手那一刻拉伸就已经生成了
3. 继续框更多矩形，允许互相重叠
4. 在右侧调方块感、像素顺序、饱和度冷暖度
5. 点「导出」合并成一张图

## 1. 效果原理

```
原始图片                       框选矩形 (x, y, w, h)              渲染结果
┌─────────────────┐           ┌─────────────────┐               ┌─────────────────┐
│                 │           │    ┌───────┐    │               │    ┌───────┐    │
│      ·          │   ──►     │    │   │   │    │      ──►      │    │███████│    │
│                 │           │    │  ↑采样 │    │               │    │███████│    │
│                 │           │    │  列   │    │               │    │███████│    │
│                 │           │    └───────┘    │               │    └───────┘    │
└─────────────────┘           └─────────────────┘               └─────────────────┘
                              取矩形内水平居中的一列           把这一列横向放大到
                              (1px 宽，贯穿矩形全高)            整个矩形宽度
```

结果：矩形内每一行像素 = 源图那一行在采样列处的颜色，横向完全均匀。天空这类纵向渐变拉伸后看不出变化，而楼、树、文字这类有横向细节的地方会被压成色带 —— 正是 Repponen 那个味道。

**核心只读原则**：每个拉伸层的采样列**永远从源图层（原图）读**，绝不读合成中间结果。叠加再多层也不会累积失真，z 序只决定「谁盖住谁」。

### 2.1 M4 的完整处理链（放大了看）

每个拉伸层的像素是这样一步步算出来的：

```
输入：矩形 (x, y, w, h)、源图层、图层参数

① 定位取样线      dir='h' → 竖线 (sx=round(x+w/2+off*w/2), sy=y, 1×h)
                  dir='v' → 横线 (sx=x, sy=round(y+h/2+off*h/2), w×1)
② 取源像素        getImageData(取样线) → 得到 len 个连续像素
③ 沿线重排        seq = buildSeq(len, L)        顺序 / 乱序 / 间序 三种置换
④ 方块分组        srcIdx(i) = seq[floor(i / block) * block]   每组只取该组首像素
⑤ 色彩调整        饱和度 → 冷暖度，逐像素
⑥ 生成成品线      dir='h' 时是 1×len 的 canvas；dir='v' 时是 len×1
⑦ 垂直放大        drawImage(成品线 → 矩形)，关闭插值 = 硬边纯色铺满

输出：矩形区域内 = 该取样线经重排/分组/调色后，沿垂直方向拉伸的结果
```

成品线会**缓存**（`getImageData` 是 GPU 回读，很贵）。缓存键包含源图 version、方向、取样线坐标、长度与全部相关参数，任一变化即失效重算。

## 3. 重叠区域的图层覆盖顺序与最终合成方式 ⭐

### 3.1 图层模型

```
       z 序（越靠上越后画，越后画越覆盖）
  ┌───────────────────────────────┐
  │  拉伸层 6   ← S.layers[n-1]    │  index 最大 = 最顶
  │  ...                          │
  │  拉伸层 0   ← S.layers[0]      │  index 最小 = 最底
  ├───────────────────────────────┤
  │  源图层（原图，固定在最底）        │  不占数组，永远先画
  └───────────────────────────────┘
```

- **源图层**：原图像素的只读副本，永远在最底，不参与排序。
- **拉伸层**：每框选一次生成一个，只存矩形几何 + 参数，**不缓存最终像素**（只缓存中间成品列）。

### 3.2 覆盖顺序规则

1. **创建顺序即堆叠顺序**：新框出的矩形直接落到最顶。
2. **数组 index 决定覆盖权**：重叠区里 index 大的盖住 index 小的 —— 标准「画家算法」。
3. **UI 列表倒序显示**：列表从上到下 = 从顶到底。拖动列表项或 `[` / `]` 实时改变覆盖归属。
4. **`Alt` + 点击**可以在重叠堆里逐层往下穿透选中（框重叠时分不清谁是谁时用）。

### 3.3 关键不变量：采样源恒定为源图层

| | 从源图层采样（本工具） | 从合成结果采样（错误做法） |
|---|---|---|
| 重叠后果 | 每个矩形内的像素精确等于原图对应列，互不干扰 | B 叠在 A 上时 B 会采到 A 已拉伸的像素 → 二次拉伸 |
| 多层叠加 | 无论叠多少层都不累积失真 | 每叠一层糊一轮，迅速糊成一片 |
| z 序的作用 | **只决定谁盖住谁**，不改变任何一层的像素内容 | z 序会连带改变像素内容，结果不可预测 |

自测里专门有一项验证：B 的采样列（x=49）正落在 A 的矩形范围内，检查它读到的仍是**原图**颜色而非 A 拉伸后的颜色。

### 3.4 最终合成的严格执行序

```js
canvas = new Canvas(round(W*倍率), round(H*倍率))

① 铺背景        bg != 'transparent' ? fillRect(0,0,W,H) : 什么都不做
② 画源图层      if (含源图层) { globalAlpha = 源不透明度; drawImage(原图, 0, 0) }

③ 依次叠加拉伸层   按数组顺序 i = 0 → n-1  （即从底到顶）
   for each L of S.layers:
       if (!L.visible) continue                    // 隐藏层跳过，不留痕迹
       save()
         globalAlpha              = L.opacity      // 默认 1.0
         globalCompositeOperation = L.blend        // 默认 'source-over' = 纯覆盖
         clip(L.x, L.y, L.w, L.h)                  // 严格裁在矩形内，绝不外溢
         sl = sampleLine(L, x, y, w, h)             // 按方向与取样偏移定出取样线
         drawImage(成品线, sl.cw, sl.ch → L.x, L.y, L.w, L.h)
       restore()

④ toBlob(格式, 质量) → 下载
```

**「覆盖」与「叠加」两种关系：**

- **覆盖（默认）**：`source-over` + `opacity=1`。上层不透明像素直接盖掉下层，这是 Repponen 原作的硬边拼贴感。
- **叠加**：调低 `opacity`，或切换混合模式 —— 正片叠底 / 滤色 / 叠加 / 差值 / 变亮 / 变暗 / 相加。混合只影响**画上去的那一步**，采样内容仍恒定取自源图层。

## 4. 自定义维度

### 4.1 方块感（纵向分组 1–100 行）

控制画面的「马赛克方块」粒度。

设分组行数为 N：矩形内每 N 行归为一组，**整组只显示该组首行的颜色**，第 2..N 行被覆盖不再显示；下一组从第 N+1 行重新开始，以此类推。

```
N = 1（默认）        N = 2                  N = 3
┌──────────┐        ┌──────────┐           ┌──────────┐
│ 第1行颜色 │        │ 第1行颜色 │  ← 首行    │ 第1行颜色 │  ← 首行
│ 第2行颜色 │        │ 第1行颜色 │  ← 被覆盖  │ 第1行颜色 │
│ 第3行颜色 │        │ 第3行颜色 │  ← 首行    │ 第1行颜色 │
│ 第4行颜色 │        │ 第3行颜色 │  ← 被覆盖  │ 第4行颜色 │  ← 首行
│ 第5行颜色 │        │ 第5行颜色 │  ← 首行    │ 第4行颜色 │
└──────────┘        └──────────┘           └──────────┘
```

分组自矩形**顶边**起算。实现上就是 `源行 = seq[floor(输出行 / N) * N]`。

**取值范围 1–100**，参考手感：

| N | 效果 |
|---|---|
| 1 | 逐行原样，细密横纹（原作那种「时间拉伸」质感） |
| 2–5 | 轻微方块感，还能看出原始结构 |
| 10–30 | 明显的马赛克色块，画面开始抽象化 |
| 50–100 | 只剩几条粗色带；矩形高度不足 N 时整块取首行，等于纯色块 |

> 滑杆够不到 1、2 这种小值，所以**方块感是滑杆 + 数字输入框**，可以直接敲数字。

### 4.2 像素顺序（乱序 / 间序）

在做方块分组**之前**，先把矩形内的竖向像素序列打乱或交错。

**乱序 (shuffle)** —— 三个参数：

| 参数 | 范围 | 含义 |
|---|---|---|
| 强度 | 0–100% | 每一步真正发生交换的概率。0 = 原序，100 = 完全打乱，中间值 = 局部错位 |
| 块大小 | 1–16 行 | 以几行为一个整体搬家。1 = 逐行打乱，8 = 每 8 行绑一起挪 |
| 种子 | 整数 | 固定种子 → 结果可复现，不会每帧闪。🎲 可重掷 |

算法是对「块数组」做带强度门限的 Fisher-Yates 洗牌，保证输出恒为原序列的一个**完整置换**（不丢行、不重复）。

**间序 (interleave)** —— 一个参数：

把竖向像素切成 `N` 段，再按「各段第 1 行、各段第 2 行、各段第 3 行…」的轮转顺序缝回去，产生规律的条带错位。

```
h=30, N=3 → 段长 10
输出序：0, 10, 20, 1, 11, 21, 2, 12, 22, …, 9, 19, 29
```

### 4.3 饱和度 / 冷暖度 + 一键随机

| 参数 | 范围 | 算法 |
|---|---|---|
| 饱和度 | −100 ~ +100 | 绕亮度轴外推：`lum = 0.2126R + 0.7152G + 0.0722B`，`C' = lum + (C − lum) × (1 + s)`。−100 变灰阶，+100 色彩浓度翻倍 |
| 冷暖度 | −100 ~ +100 | 乘性偏移，保留黑场：`R×=(1+0.30w)`，`G×=(1+0.06w)`，`B×=(1−0.30w)`。正值偏暖，负值偏冷 |

**随机**：
- 「🎲 本层随机（饱和度 + 冷暖）」按钮，或按 `R` 键 —— 只作用于当前选中的层
- 「🎲 全部图层随机」—— 批量作用于所有层，同时重掷乱序种子
- **随机强度**（0–100）决定摆动幅度：生成值落在 `[−强度, +强度]` 内

### 4.4 拉伸方向 · 取样偏移

**方向**决定「取哪一条线、往哪儿拉」：

| 方向 | 取样线 | 拉伸方向 | 典型用法 |
|---|---|---|---|
| 水平（默认） | 矩形内一条**竖线**（宽 1px，高 = 矩形高） | 左右铺满 | Repponen 原作的横向撕裂感 |
| 垂直 | 矩形内一条**横线**（高 1px，宽 = 矩形宽） | 上下铺满 | 竖向拉伸／地表、水面、幕布的纵向流动 |

画框时按住 **Shift** 可临时反转方向；左侧「默认方向」决定新框默认用哪个。
管线的其余部分（方块感、乱序/间序、色彩）都是方向无关的，跟着取样线一起走。

**取样偏移**让取样线不再固定居中：

```
sampleOff = −100          0（默认）          +100
        ┌───┬───────────┬───┐
        │   │           │   │
        │ 取样线在左边缘 │ 居中 │ 右边缘
        └───┴───────────┴───┘
```

- 取值范围 −100 ~ +100，单位是**半宽/半高的百分比**：−100 = 左/上边缘，0 = 居中，+100 = 右/下边缘
- 水平模式下偏移的是 x，垂直模式下偏移的是 y
- 画布上**每一层都会画出自己的取样线**（黄线），选中的那条更亮，属性面板还会显示它的像素坐标

> 取样线位置 = `round(矩形中心 + 偏移% × 半宽)`，再钳进矩形范围内。

### 4.5 批量生成框（快速网格 / 随机框选）

三套里保留两套自动落框的方式，参数都在左侧面板、随工程一起存。

#### 快速网格（不等分随机切）

把画面切成 列 × 行 个矩形，**但每格大小不等**。

| 参数 | 说明 |
|---|---|
| 列数 / 行数 | 目标格数（上限 60×60 = 900 格） |
| 尺寸随机 | 0 = 完全等分；越大宽窄差越夸张（默认 45） |
| 相邻重叠 | 按格子自身尺寸的百分比向两侧外扩，制造重叠（上限 60%） |

算法不是「等分再随机挪边界」（那样容易挤出极窄格或越界），而是**加权分配**：

```
1. 给每一格抽一个权重 w_i = 1 ± 0.9×随机度   （最小钳到 0.05）
2. 第 k 个切点 = round( Σ_{i≤k} w_i / Σ w × 总长 )
3. 首尾锚定 0 / 总长，强制严格递增（至少留 1px）
```

每格都按权重拿到长度，**天然不会越界、不会出现零宽格**，随机度 100 时最窄和最宽能差到 5 倍以上。
点「🎲」按钮可以换一批随机切法。

#### 随机框选

每次点一下，就往画面里丢 N 个**随机位置、随机尺寸**的框。

| 参数 | 说明 |
|---|---|
| 宽度 | 占画面宽度的百分比区间，默认 8% ~ 40% |
| 高度 | 占画面高度的百分比区间，默认 20% ~ 100%（默认偏「竖条」，接近原作构图） |
| 个数 | 一次丢几个，1–50 |

宽/高区间写反了会自动交换；框一律钳在画面内；新框的拉伸方向跟随左侧「默认方向」。

### 4.6 图层位置锁定 · 剪贴板 · 画布导航

#### 位置锁定

锁定后的图层**不能拖动、不能缩放、方向键也推不动**，但仍然可以选中、改参数、改顺序、删除。
用途：主体区域的框调好之后锁住，避免后面框其他区域时误拖。

- 属性面板「🔓 锁定位置 / 🔒 解锁位置」按钮，或按 **`L`**
- 图层列表行上会出现 🔒 标记，点它可直接解锁
- 锁定后 X / Y / 宽 / 高 四个输入框变灰不可编辑，画布上也不绘制 8 个控制点

#### 图层剪贴板

| 快捷键 | 作用 |
|---|---|
| `Ctrl`+`C` | 复制选中层（含全部参数：方向、偏移、方块感、顺序、色彩、混合） |
| `Ctrl`+`X` | 剪切 |
| `Ctrl`+`V` | 粘贴。**连续按会逐次错开**，不会全叠在同一位置 |
| `Ctrl`+`Shift`+`V` | 从系统剪贴板粘贴**图片**（和图层粘贴区分开） |
| `Ctrl`+`D` | 原地复制一份（不动剪贴板） |

#### 画布导航

平移画布有四条路，按顺手的用：

1. **拖动右下角小地图** —— 最省事。小地图显示整图 + 各图层轮廓 + 当前视口矩形
2. **右键拖拽** —— 不用先按空格
3. 空格拖拽 / 中键拖拽
4. **未选中任何图层时按方向键** —— 平移画布（选中图层时方向键仍然是微调位置）

### 4.7 设置 · 默认目录

右上角「设置」（或 `Ctrl`+`,`）可以把三项默认目录固定下来：

| 项目 | 影响 |
|---|---|
| 图片导入 | 「导入图片」对话框的起始目录 |
| 导出图片 | 导出 PNG/JPG/WebP 时「另存为」的起始目录 |
| 工程文件 | 保存 / 打开 `.json` 工程时的起始目录 |

- **桌面版**：设置存到 `%APPDATA%\时间拉伸\settings.json`，重开依然有效，
  并且是通过 Electron 的 IPC 真正作用到系统对话框上的。
  目录被删掉或失效时会自动退回系统默认位置，不会弹到一个不存在的路径。
- **网页版**：受浏览器限制，没有文件系统权限，设置项只能记住但无法影响系统对话框 —— 面板里会明确提示。

色彩调整只作用于矩形内的像素，框外原图不受影响。

### 5.1 界面结构与设计规则

#### 几条硬规则

- **不许用描边分区域。** 输入框、按钮、分段控件全是纯填充、零 border。需要边界的地方靠明度差，不靠 1px 灰线。
- **不许出现原生控件。** 数字框的 `▲▼`、下拉框的默认箭头、checkbox 的默认样式都要么干掉要么重画。你一句「上下调整的按钮太丑」，根因是整套设计里混进了操作系统控件。
- **标签可拖。** 所有滑杆行的标签都是 scrub 热区：左右拖连续调参，`Shift` ×10、`Alt` ×0.1，双击回 `data-def`。改参数靠手感，不靠点滑杆。
- **强调色不许扩散。** 图层行的一排「眼睛」图标一度全是蓝色，一屏十几个蓝点把选中态淹没了 —— 现在眼睛是中性色，只有选中行整条实心蓝。
- **属性面板里没有滑杆。** 数值行只有两样东西：**数字框 + 框内左侧的小图标**。图标就是拖拽热区（`Shift` ×10、`Alt` ×0.1、双击回默认值），文字标签只负责说明，不抢手势 —— 两个都能拖会互相打架。
- **启动页先于编辑器**：打开软件先看到「最近工程」网格（IndexedDB 里的工程 + 缩略图），点卡片或新建/打开后才进编辑器。
- **标签在上、控件在下，短标签一行两个**（`.cells` 两列）。「标签靠左 / 数值靠右」会在中间留出一条空带，短参数尤其难看。X/Y、宽/高、饱和度/冷暖度、强度/块大小 都是成对排。
- **改数值不重建 DOM。** 上下限用函数现算（`() => ({min, max})`），而不是每次 `change` 后 `renderAll()` —— 后者会让输入框打完字就失焦、拖标签中途断掉。
- **展开分组走高度过渡**：`::details-content` 的 `block-size: 0 → auto` 配 `interpolate-size: allow-keywords`，保留 `<details>` 的键盘与语义，不用量高度写死 `max-height`。
- **折叠分组要留下信息。** 收起后的摘要直接带当前值：`92 × 440`、`↔ 水平 · +45%`、`S+90 W0`、`5 px`。展开状态靠 `grpOpen` 对象跨 `renderProps` 重建保持。
- **画布叠加层必须读主题。** 选中框、取样线、控制点、锁定徽标原来都是写死的颜色，浅色主题下白色控制点直接看不见。现在统一走 `PAL`。
- **棋盘格换成点阵。** 棋盘格暗示「透明区域」，但这个工具的画布永远有不透明底，用它属于误用符号。

#### 主题

`html[data-theme="dark"|"light"]` 切换整套令牌，顶栏按钮切换、记在 `localStorage`，默认深色。
深色利于判断明度关系，浅色利于判断饱和度 —— 两个都留着。
分段控件的选中态用独立令牌 `--seg-on`（深色 `#3a3a3a` / 浅色 `#ffffff` + 投影）：
浅色主题下「浅灰底 + 更浅灰」等于没有选中态，这个只有真正截图看才发现。

## 6. 桌面版（.exe）

### 6.1 产物

```
dist/时间拉伸-win32-x64/
├── 时间拉伸.exe        ← 双击这个
├── resources/app/      ← 程序本体（index.html + main.js + preload.js）
├── *.dll / locales/    ← Electron 运行时
└── ...
```

**必须保持整个文件夹在一起**：`时间拉伸.exe` 依赖同目录下的 Electron 运行时，单独把 exe 拷走会打不开。想放桌面就给它建个快捷方式。

> **只改了界面代码、没改 Electron 主意程时，不必重打包。**
> 直接覆盖 `resources/app/index.html` 就行，下次启动即生效（`_build_portable.js` 的第 2 步做的就是这件事）。
> 反过来，**应用开着的时候打包会 EPERM** —— 运行中的 exe 被占用无法改名。脚本会重试 8 次再报错，
> 真遇到就先关掉应用。

### 6.2 桌面版相对网页版多了什么

- 独立窗口，无浏览器地址栏/标签页
- 导出图片、保存工程时弹**原生「另存为」对话框**（默认落到「图片」文件夹）
- 原生菜单：文件（打开/保存工程）、视图（重载 / 全屏 / F12 开发者工具）、帮助（关于）
- 自带应用图标（`icon.ico`，7 种尺寸，图案就是本工具的效果本身）

### 6.3 自己重新打包

```bash
npm install                    # 首次；Electron 二进制走 npmmirror 镜像
node _make_icon.js             # 生成 icon.ico
node _build_portable.js        # 组装 dist/时间拉伸-win32-x64/
npm start                      # 不打包，直接以 Electron 跑，方便调试
```

**为什么没用 electron-packager**（`package.json` 里保留了 `npm run build` 作为备选）：
它要先把 157MB 的 electron zip 解压到临时目录再拷到产物目录，两次 368MB 的 I/O。
本机实测解压只有 ~100KB/s，估时 **47 分钟**；而 `node_modules/electron/dist` 里已经有解压好的
运行时，用 `robocopy` 直接拷过去 **0.1 秒**就完事。`_build_portable.js` 就是干这个的，
图标和版本信息用纯 JS 的 `resedit` 写进 PE（不需要任何外部 exe）。

**踩过的坑**（都写进脚本注释了）：

| 坑 | 现象 | 解法 |
|---|---|---|
| `fs.cpSync` 批量写文件 | node 进程被沙箱静默杀掉，EXIT=127，**没有任何报错** | 换 `robocopy`（单个外部进程，一次跑完 368MB 没问题） |
| Git Bash 路径转换 | `robocopy ... /E` 被 MSYS 当成路径参数，退出码 16 并打印用法帮助 | 命令前 `export MSYS_NO_PATHCONV=1` |
| 打包版拒绝未知开关 | `时间拉伸.exe --selftest` 报 `bad option` 秒退 | 用**位置参数**（`selftest`），别用 `--xxx` |
| `ELECTRON_RUN_AS_NODE` | 若环境里有这个变量，exe 会以纯 Node 模式启动，把 `selftest` 当脚本文件找 | 从 IDE 终端里跑要先 `unset`；普通双击不受影响 |

### 6.4 内置自检

打包后的 exe 自带两个验证入口（也可以用浏览器版跑同一套）：

```bash
时间拉伸.exe selftest   # 把 _selftest_inject.js 注入页面跑完整 322 项自检，
                       # 结果写 %TEMP%\timestretch-selftest.txt，退出码 0=全过 1=有失败
时间拉伸.exe smoke      # 跑完整正常路径（建菜单 + 建窗口）但不开可见窗口，
                       # 仅验证窗口/菜单创建不崩，结果写 %TEMP%\timestretch-smoke.txt
```

> 自检与冒烟模式会把 Electron 的 `userData` 重定向到临时目录，
> **不会碰你 `%APPDATA%\时间拉伸\settings.json` 里的真实目录配置**。

自测用**两张诊断图**，每个像素值都能独立反推它到底采了哪一行/哪一列，
所以断言是像素级精确而不是「看起来差不多」：

- **列渐变图**（第 x 列纯色 `rgb(2x,0,255-2x)`）→ 验证水平方向「采了哪一列」
- **行渐变图**（第 y 行纯色 `rgb(4y,0,255-4y)`）→ 验证垂直方向「采了哪一行」，
  以及方块感 / 乱序 / 间序唯一可测的方式

- `node _gen_shots.js` —— 出 4 张状态图（空状态 / 未选中 / 导出弹窗 / 浅色空状态）。
  注意：`--screenshot` 会把正在跑 CSS 动画的元素截成半透明，看起来像「弹窗是透明的」。
  脚本里临时注入了 `animation:none` 才拍得准 —— 别被这个假象骗到。
- `node _png.js <png> x,y ...` —— 手写的 PNG 像素读取器（zlib 解压 + 5 种 filter），
  用来逐像素核对「浅色主题到底有没有生效」。同一份截图，肉眼说是深色、像素说 `rgb(246,246,248)`，
  **以像素为准**。

## 8. 迭代修复记录

### v12（本轮）—— 下拉不再被裁、分段滑动、弹窗好关

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| 1 | 下拉展开后**被下一个分组盖住 / 截断** | 右侧面板是滚动容器（`overflow-y:auto`），`details` 的内容区还有 `overflow:hidden` + `content-visibility` 包含块。弹层留在这里，`absolute` 会被裁、`fixed` 也不行 | 改成**真正的 portal**：打开时把列表 `appendChild` 到 `body`，用按钮的 `getBoundingClientRect()` 现算位置；下方放不下自动翻到上面。滚动 / 改窗口大小时收起 |
| 2 | 下拉按钮不该有按下回弹 | 它继承了全局 `button:active{transform:scale(.955)}` | 下拉是靠右侧小三角拉开的，不是按下型按钮 —— `.dd-btn` / `.dd-opt` 单独取消形变 |
| 3 | 设置里的三连按钮切换时**色块突变** | 每个按钮自己换底色 | 改成**滑动色块**：`.seg` 里放一个 absolute 的 `.seg-thumb`，宽度按按钮数均分，切换时 `translateX` 滑过去 |
| 4 | 快捷键页要滚到底才能关 | `.cardm{overflow:auto}` 把底部按钮一起滚了 | 拆成 `.cardm-body`（独立滚动）+ `.btns`（固定底栏，带分隔线）；三个弹窗右上角都加了 ×；`Esc` 也能关 |

## 9. 已知边界

- **不支持旋转矩形**。取样线必须是轴对齐的，「居中列 / 居中行」的定义才成立。
- **矩形不能超出图像范围**，超出部分没有源像素可采，一律裁掉。
- **导出倍率只有 0.5x / 1x / 2x**。2x 是纯上采样放大，不增加真实细节。
- **工程 JSON 会内嵌原图的 PNG dataURL**，大图（如 4000×3000）可能到几十 MB，属正常现象。
- **乱序是「完整置换」**，只改变取样线上像素的排列顺序，不会凭空生成新颜色，也不会丢失原有像素。
- **取样偏移的 −100 / +100 是半宽百分比，不是像素值**：矩形半宽 20px 时 +100 表示往右偏 20px，
  正好落在右边缘（再往外也没有源像素可采，会被钳住）。
- **网页版用不了「设置 · 默认目录」**，浏览器没有文件系统权限，面板里会明确提示。
- **桌面版不是单文件 exe**，`时间拉伸.exe` 必须和同目录的运行时文件放在一起。
- **自检用的 `selftest` / `smoke` 是位置参数**，写成 `--selftest` 会被 Chromium 命令行解析器拒绝。
- **`_selftest_inject.js` 会随包发布**（`resources/app/` 里），它是 `selftest` 模式的测试体。
  不需要自检功能的话可以删掉它，不影响正常使用。
- **从 IDE 终端里启动 exe 要先 `unset ELECTRON_RUN_AS_NODE`**：这个环境变量会让 Electron
  以纯 Node 模式启动、把参数当脚本文件找。普通双击不受影响。
